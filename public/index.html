What this is
Lets external automation (curl, Ansible, CI) reach a lab node's real management API through this app, at /api/relay/<lab>/<node>/<path> -- plain pass-through, no stored device credentials. Off by default; needs a token.
Example
# relay token goes in its own header (X-Labber-Relay-Token), not
# Authorization -- that one is left free for the device's own auth.
curl -H "X-Labber-Relay-Token: <your token>" \
     -H "Authorization: Bearer <the device's own token, if it needs one>" \
     https://<this app's hostname>/api/relay/<lab>/<node>/<path-on-the-device>

# e.g. a FortiGate node named "fgt1" in a lab named "the-big-lab":
curl -H "X-Labber-Relay-Token: lbr_...token..." \
     https://labber.example.com/api/relay/the-big-lab/fgt1/api/v2/cmdb/system/status
Try it
Fires a real request through the relay, from this browser -- confirms the same path your automation would use actually works end to end (relay enabled, token valid, node reachable).

Console access

              

                A real Proxmox username/password, separate from the API token
                above. Proxmox has a confirmed bug where API tokens aren't
                accepted for console/termproxy access (bugzilla #6079) --
                everything else in this app keeps using the API token; only
                opening a node's console needs this.

Template VMID auto-pick range

              

                Where the templates builder looks for a free VMID by default,
                instead of Proxmox's own "lowest free ID cluster-wide" (which
                tends to land right next to your manually-numbered VMs). Doesn't
                affect lab-manager's own 9000-9999 range for ephemeral lab
                clones. You can also type an exact VMID per-build in the
                templates modal, which ignores this range entirely.
              

              

              
Upload rate limit

              

                Caps how fast this modal's file upload writes to disk. This app's
                storage can share a physical disk with other latency-sensitive
                things (e.g. k3s/etcd on a resource-constrained node) -- a
                full-speed multi-GB write can starve that badly enough to disrupt
                the node mid-upload. 0 = unlimited. Takes effect on the very next
                upload, no restart needed.
              

              

              
Golden template VMIDs

              

                Every device kind the app knows about, and whether it has a
                template built yet -- generated from the same list the
                templates modal's kind picker uses, so a newly added kind
                always shows up here automatically. "edit hw" adjusts an
                already-built template's hardware directly -- Proxmox leaves a
                template's non-disk config editable even after `qm template`,
                only the disk itself becomes read-only.
              

              


              

                

                
                
                
                
                
                
                
                
                
                

              

            


            

              
Embedded GUI proxy

              

                Lets a running node's real web UI open embedded in an iframe
                (dashboard's "web rp" button) via a Host-header-routed subdomain,
                instead of only a plain new-tab link. Requires a wildcard DNS
                record and a reverse-proxy/Ingress rule for
                *.<each domain> pointing at this app's
                gui-proxy port (see README) -- set up outside this app. Blank
                disables the feature ("web rp" button falls back to new-tab).
                Accepts a comma-separated list -- if the main dashboard itself
                is reachable via more than one hostname (e.g. a plain one and
                a direct-ingress bypass that skips a reverse proxy in front),
                list a GUI domain for each, or web-rp will 404 on every
                hostname not included.
              

              
            


            

              
              
            

            

          


          

            
Remote stats API

            

              Exposes a read-only /api/public/stats endpoint (lab
              count, active labs, VM count, Proxmox node CPU/mem/disk) with no
              login required -- for external consumers like a homepage's
              lab-status widget. Off by default.
            

            

              
              
              

                
              

              

            


            

              
API relay (for automation)

              

                Lets external automation (curl, scripts, CI) reach a lab
                node's real management API through this app, via
                /api/relay/<lab>/<node>/<path>
                on this app's own domain/port -- no VPN or route to the
                lab's management network needed from wherever the
                automation runs. Plain pass-through: your request (method,
                headers, body, and whatever auth the device itself expects)
                is forwarded byte-for-byte to
                https://<node's mgmt IP>:<mgmt port>/<path>
                -- this app does not store or inject device credentials, so
                your request's own Authorization header (if
                the device needs one) reaches the device untouched. Gated
                by a token below, sent as
                X-Labber-Relay-Token: <token> (a separate
                header from Authorization on purpose). Off by
                default.
